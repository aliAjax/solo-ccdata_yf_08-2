# 战役复盘与行动调度台

本地优先的战役行动调度应用（React + Vite，无后端）。数据保存在浏览器
`localStorage`，刷新不丢失；全部写操作可撤销/重做并自动写入「变更留痕」。

## 运行

```bash
npm install
npm run dev        # 开发
npm run build      # 生产构建 → dist/
npm run preview    # 预览构建产物
```

## 功能

- **基础数据维护**：阵营、部队、军官、地点（含开放时段）、物资（库存/占用），
  删除时提示被引用位置。
- **行动**：编号、标题、开始/结束时段、部队、负责人、目标地点、优先级（P1–P5）、
  依赖行动、物资消耗、备注。
- **批准校验（拒绝时指出冲突对象，可一键跳转）**：
  1. 同一部队在时段重叠时已分派给另一行动；
  2. 依赖成环（DFS 检测，给出环路径）；
  3. 物资库存不足（已批准/执行中的占用计入，给出需要量与剩余可用量）；
  4. 行动时段超出目标地点开放时段；
  另：前置仍是草稿、引用悬空等也会拦截。批量批准时还做**批内互查**
  （同部队时段、物资合计），可选择「仅批准通过的」。
- **状态流转**：草稿 → 已批准 → 执行中 → 已完成；批准可撤回、执行可暂停；
  已完成只能**填写原因重开**（原因留痕并显示在行内）。
- **调度**：按优先级/时段/状态/编号排序，状态与部队筛选，仅看逾期，
  勾选后批量批准、批量分派（部队/负责人/优先级）。
- **留痕**：所有编辑、流转、批量、导入、撤销/重做自动入审计日志，可按类型过滤。
- **导入/导出**：版本化 JSON（`version: 1`）。导入**逐项校验**——版本号、
  id 唯一性、引用完整性、ISO 时间、库存非负、依赖环、**负责人必须属于所选部队**
  等；并且文件中**已批准/执行中的行动会用与调度台相同的规则重放调度校验**
  （同时段同部队、依赖状态、地点开放时段、物资余量、归属），任一项失败整体拒绝，
  **不覆盖现有数据**，错误精确到 JSON 路径（如 `$.data.actions[0]`）；
  通过后需二次确认，导入本身可撤销。所有时间比较按**真实时刻（epoch 毫秒）**，
  带时区偏移的 ISO 文本不会被字符串排序误判。
- **批量分派**：换部队时必须同时选择属于新部队的负责人；跨部队多选时负责人下拉
  只列相关部队的军官；归属不一致整单拦截且不落盘。
- **撤销/重做**：侧栏按钮或 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z；历史栈一并持久化。

## 测试

```bash
npm run test:model   # 模型层：时区时刻比较 / 归属 / 批量分派 / 导入语义（16 项）
npm run build        # 生产构建
npm run e2e          # Playwright 浏览器端到端（需先 npx playwright install chromium）
```

`e2e.mjs` 覆盖：批准拦截（四类冲突）、状态流转、批量批准与**改派归属拦截**、
重开原因强制、**导入既定状态冲突 / 时区偏移伪装 / 时区合法**、导入失败不覆盖、
刷新恢复（含撤销栈）。最近一次：模型 16/16、浏览器 **73/73 全部通过**
（截图见 `e2e-*.png`）。
